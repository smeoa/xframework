# 技能：需求拆解

## 1. 功能描述

**仅处理1.TODO.md中用户指定编号的单个待办需求**，将其转化为标准化PRD模块并追加到2.PRD.md中。不处理其他任何需求，不修改任何其他文档内容。

## 2. 输入输出

- **必选输入参数**：`任务编号`（如：1、2、3）
- **只读输入**：`1.TODO.md`（仅读取指定编号的需求内容）
- **可写输出1**：`2.PRD.md`（仅追加指定编号的模块内容，原有内容完全保留）
- **可写输出2**：`1.TODO.md`（仅将指定编号的需求状态从`[]`改为`[已拆解为PRD]`，其他需求完全不变）
- **绝对禁止**：修改PRD中已存在的其他模块、删除任何内容、创建或修改其他文件

## 3. 执行步骤（AI严格按顺序执行）

### 步骤1：参数校验与文件读取

1. 确认用户提供了有效的任务编号（正整数）
2. 读取`1.TODO.md`文件，**仅提取指定编号的需求项**
3. 检查该需求状态是否为`[]`（待处理），如果已是`[已拆解为PRD]`则直接返回"任务已完成"
4. 检查`2.PRD.md`是否存在，不存在则创建空文件；存在则读取原有内容，**不做任何修改**

### 步骤2：单需求拆解（仅处理指定编号）

对提取的单个需求项，按以下模块生成内容：

- 需求概述（价值、目标、用户场景）
- 功能模块（边界明确，含"什么不做"）
- 业务流程（主流程+异常分支）
- 业务字段与交互要求
- 验收标准（可量化）

### 步骤3：增量更新文件

1. **追加模式写入PRD**：将生成的指定编号模块内容添加到`2.PRD.md`文件末尾，原有内容完全保留
2. **原子更新TODO**：仅修改`1.TODO.md`中指定编号需求的状态，将`[]`改为`[已拆解为PRD]`，其他所有行保持原样
3. 不修改任何其他文件或内容

## 5. AI执行铁律（违反视为错误）

1. **仅处理指定编号**：绝对不处理其他任何编号的需求
2. **仅追加不覆盖**：PRD文件只能在末尾追加内容，原有内容一字不改
3. **仅修改指定状态**：TODO文件只能修改指定编号需求的状态，其他行完全不变
4. **不碰其他文件**：绝对不创建、修改、删除WBS、DB相关的任何文件
5. **幂等性保证**：重复执行同一任务编号，不会重复追加PRD内容，只会确认状态
