# 技能：WBS拆解

## 1. 功能描述
**仅处理2.PRD.md中用户指定编号的单个模块**，将其转化为技术任务并追加到3.WBS.json和3.WBS.md中。不处理其他任何模块，不修改任何其他文档内容。

## 2. 输入输出
- **必选输入参数**：`模块编号`（如：1、2、3）
- **只读输入**：`2.PRD.md`（仅读取指定编号的模块内容）
- **可写输出1**：`2.PRD.md`（仅将指定模块的标题状态从`# X. 名称`改为`# X. 名称[已拆解为WBS]`）
- **可写输出2**：`3.WBS.json`（仅追加指定模块的任务数组，原有任务完全保留）
- **可写输出3**：`3.WBS.md`（仅追加指定模块的任务表格，原有内容完全保留）
- **绝对禁止**：修改WBS中已存在的其他模块任务、修改数据库设计相关文件、删除任何内容

## 3. 执行步骤（AI严格按顺序执行）
### 步骤1：参数校验与文件读取
1. 确认用户提供了有效的模块编号（正整数）
2. 读取`2.PRD.md`文件，**仅提取指定编号的模块内容**
3. 检查该模块状态是否未标记`[已拆解为WBS]`，如果已标记则直接返回"任务已完成"
4. 检查`3.WBS.json`和`3.WBS.md`是否存在，不存在则创建初始结构；存在则读取原有内容，**不做任何修改**

### 步骤2：单模块任务拆解（仅处理指定编号）
对提取的单个PRD模块，按以下类型拆解任务：
- 数据库设计任务（DB）：每个核心实体1个任务
- 后台API开发任务（BA）：每个功能点的增删改查各1个任务
- 后台前端开发任务（BF）：每个页面/组件1个任务
- 联调测试任务（JT）：每个子模块1个任务

严格遵守2-8小时单任务粒度标准，生成符合规则的WBS编号。

### 步骤3：增量更新文件
1. **原子更新PRD**：仅修改`2.PRD.md`中指定模块的标题，添加`[已拆解为WBS]`标记，其他所有内容完全不变
2. **追加模式写入WBS.json**：将生成的指定模块任务数组添加到`3.WBS.json`的`tasks`数组末尾，原有任务完全保留
3. **追加模式写入WBS.md**：将生成的指定模块任务表格添加到`3.WBS.md`文件末尾，原有内容完全保留
4. 不修改任何其他文件或内容

## 5. AI执行铁律（违反视为错误）
1. **仅处理指定编号**：绝对不处理其他任何编号的PRD模块
2. **仅追加不覆盖**：WBS文件只能在末尾追加内容，原有任务一字不改
3. **仅修改指定标题**：PRD文件只能修改指定模块的标题状态，其他所有内容完全不变
4. **不碰其他文件**：绝对不创建、修改、删除TODO、DB相关的任何文件
5. **编号不冲突**：新增任务的WBS编号必须与已有编号不重复，严格遵循编号规则
